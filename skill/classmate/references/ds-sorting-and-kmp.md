# 排序与 KMP

## 归并排序

### 解决的问题与直觉

归并排序利用“两个有序序列很容易合并”：不断把大数组拆成更小的两半，直到单个元素天然有序，再把相邻有序段合起来。

### 小例子

`[4,1,3,2]`：

1. 拆成 `[4,1]` 与 `[3,2]`；
2. 继续拆成单个元素；
3. 合并得到 `[1,4]` 与 `[2,3]`；
4. 比较两个有序段的开头，依次取出 `1、2、3、4`。

合并时维护两个指针，分别指向左右有序段中尚未取出的最小元素。每次选择较小者不会错，因为两个段内部已经有序。

### 复杂度、稳定性与误区

每层合并处理 n 个元素，共约 `log n` 层，因此时间 `O(n log n)`；数组实现通常需要 `O(n)` 辅助空间。相等时先取左段元素才能保持稳定。拆分本身不会排序，真正产生有序结果的是合并。

## 快速排序

### 解决的问题与直觉

快速排序先选一个轴点 pivot，通过划分让较小元素去一侧、较大元素去另一侧，再递归处理两侧。一次划分不会让整个数组有序，只确定轴点位置或三个值域区域。

### 划分时维护什么

不同 partition 实现的指针和最终排列可以不同，回答前必须说明采用哪一种。共同不变式通常是：已经扫描过的左侧区域满足 `< pivot`，右侧区域满足 `> pivot`，中间是尚未分类部分。

### 为什么平均快、最坏会慢

每次划分扫描当前区间，成本为 `O(n)`。若轴点大致把数组平分，递归约 `log n` 层，总时间 `O(n log n)`；若固定取端点且输入有序，每次只分出一个元素，递归深度接近 n，总和退化为 `O(n²)`。

随机选择轴点只能降低连续坏划分的概率，不能消灭理论最坏情况。大量重复元素时，三路划分把数据分成 `< pivot、== pivot、> pivot`，等于区无需递归。

### 常见误区

- 不能脱离具体 partition 规则断言“第一次划分后数组唯一是什么”；
- 左右指针和 pivot 相等时必须保证每轮有进展，否则可能死循环；
- 快排通常不稳定；递归栈平均 `O(log n)`，最坏可能 `O(n)`。

## 排序稳定性

### 含义

若两个元素的排序关键字相等，排序后仍保持它们原来的相对先后次序，这个排序实现就是稳定的。

例如学生记录先按姓名录入，再按分数排序。两名学生同分时，如果仍保持原录入顺序，就是稳定；稳定性对多关键字分阶段排序很重要。

### 常见结论

- 冒泡排序、插入排序、归并排序可以稳定；
- 选择排序、快速排序、堆排序通常不稳定；
- “算法可以稳定”仍取决于实现，例如归并时相等却先取右段会破坏稳定性。

稳定性与时间复杂度、是否原地是三个不同维度。排序数值看起来正确，不代表相等对象的附加信息顺序也正确。

## 比较排序下界

### 要说明的结论

只通过两两比较决定顺序的通用排序算法，最坏情况下不能突破 `Ω(n log n)` 次比较。

### 决策树直觉

n 个互异元素可能有 `n!` 种排列，算法必须区分每一种。一次二元比较只有两种结果，可看成决策树的一次左右分支；要拥有至少 `n!` 个叶子，树高至少为 `log₂(n!)`，其数量级是 `n log n`。

### 适用边界

这个下界只限制基于比较的通用排序。计数排序、桶排序和基数排序利用关键码范围或数位等额外条件，不完全依靠比较，因此可以在线性时间完成特定输入，但会付出空间或适用范围限制。

## KMP 逐步执行

### 解决的问题与直觉

暴力匹配失配后会让主串回退，重复比较已经匹配过的字符。KMP 利用模式串自身“前缀和后缀相同”的信息，只移动模式串，主串指针不回退。

### 维护的状态

- `i`：主串当前比较位置；
- `j`：模式串当前比较位置，或已经匹配的长度；
- 前缀表：失配后 j 应回到哪里。

若已经匹配的部分末尾与模式串开头相同，这段开头不必重新和主串比较，可直接保留。

### 匹配过程示例

主串 `abababaca`，模式串 `ababaca`。前五个字符 `ababa` 匹配后，在主串下标 5 的 `b` 与模式串下标 5 的 `c` 处失配。

模式串 `ababa` 的最长相等真前后缀是 `aba`，所以 j 从 5 回到 3，i 仍停在主串下标 5。接下来比较主串 `b` 与模式串下标 3 的 `b`，继续匹配，最终在主串下标 2 找到模式串。

### 两种常见表定义

回答前必须声明采用哪一种约定，不能把数组和匹配代码混用。

1. **LPS/前缀函数长度定义**：`lps[j]` 表示模式串 `P[0..j]` 的最长相等真前后缀长度。`ababaca` 的 LPS 为：

   ```text
   [0, 0, 1, 2, 3, 0, 1]
   ```

   匹配失配时通常写成 `j = lps[j-1]`。

2. **经典 next 下标定义**：令 `next[0] = -1`，失配时直接执行 `j = next[j]`。与上面 LPS 对应的一种结果为：

   ```text
   [-1, 0, 0, 1, 2, 3, 0]
   ```

   对 `j >= 1`，这里的 `next[j]` 对应 `lps[j-1]`。

有的教材把 next 整体平移、使用 1-based 下标，或者采用 nextval，所以网上数组看起来不同不一定有人算错；判断关键是定义、构表代码和匹配代码必须一致。

### 复杂度与误区

构表 `O(m)`，匹配 `O(n)`，合计 `O(n+m)`。KMP 不会让模式串完全不回退，回退的是模式串位置 j；不回退的是主串位置 i。前缀和后缀必须是真前后缀，不能把整个串本身算进去。
