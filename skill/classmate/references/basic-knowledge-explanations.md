# 基础知识点解释

本文根据 `course-knowledge-trees.md` 中的 `EXPAND/EXPEND` 标记整理，用于后续写入 OOP / 程设学习助手 skill。解释风格面向低年级学生：先讲直觉，再讲常见误区，必要时给出短代码。

## 程序设计基础

### 变量、变量值与内存

变量可以理解为“有名字的小盒子”。变量名是程序里用来找到盒子的名字，变量值是盒子里当前放着的数据，变量内存是计算机实际存放这个盒子的空间。

```cpp
int x = 10;
x = 20;
```

这里 `x` 是变量名，`10` 和后来的 `20` 是变量值。`x = 20` 只是改变变量保存的值，不是重新创建一个变量。

常见误区：

- `int x;` 只是定义变量，不等于它一定有可用初值。
- `x = 3;` 是赋值，`x == 3` 是比较。
- 变量类型决定它能保存什么样的数据，也影响表达式计算结果。

### 初始化与赋值

初始化是在变量创建时给初值，赋值是在变量已经存在之后修改值。

```cpp
int a = 0;  // 初始化
a = 5;      // 赋值
```

局部变量如果只写 `int a;`，它的值是不确定的。初学者 debug 时，如果发现输出结果很奇怪，要优先检查变量有没有初始化。

### 类型转换

类型转换是把一种类型的值转换成另一种类型的值。

```cpp
int a = 5;
int b = 2;
double x = a / b;          // 结果是 2.0
double y = 1.0 * a / b;    // 结果是 2.5
```

`a / b` 中两个操作数都是 `int`，所以先做整数除法，得到 `2`，再转成 `double`。类型转换改变的是参与计算的值，不会把原变量永久改成另一种类型。

### 指针

指针变量保存的是地址。普通变量保存数据，指针保存“数据在哪里”。

```cpp
int x = 10;
int* p = &x;
cout << p << endl;   // x 的地址
cout << *p << endl;  // 地址里的值，也就是 10
```

常见误区：

- `p` 是地址，`*p` 是地址指向的值。
- `&x` 是取地址。
- 指针类型很重要，`int*` 表示这个地址里应该按 `int` 解释。
- 数组名在很多表达式中会退化成首元素地址，但数组不是普通指针变量。

### 输入输出：cin、getline、scanf

`cin >> x` 适合读一个单词或一个数字，遇到空格、换行会停下。`getline(cin, s)` 适合读一整行文本。

```cpp
string name;
getline(cin, name);
```

如果先用 `cin >> n`，再用 `getline`，要注意上一行末尾的换行可能还留在输入缓冲区中。

```cpp
int n;
cin >> n;
cin.ignore();
string line;
getline(cin, line);
```

`scanf` 是 C 风格输入，速度快但格式要求严格，例如 `scanf("%d", &x);`。在 C++ 初学阶段，优先掌握 `cin/cout`，再理解 `scanf/printf` 的格式化写法。

### 文件输入输出

文件输入输出可以把原本从键盘读入、输出到屏幕的过程改成读写文件。

```cpp
#include <fstream>
using namespace std;

ifstream fin("input.txt");
ofstream fout("output.txt");

int x;
fin >> x;
fout << x * 2 << endl;
```

如果文件打不开，常见原因是文件路径不对、文件不在程序运行目录中、没有权限。调试时可以先判断：

```cpp
if (!fin) {
    cout << "file open failed" << endl;
}
```

### switch 分支

`switch` 适合根据一个离散值选择分支。

```cpp
switch (op) {
case '+':
    cout << a + b;
    break;
case '-':
    cout << a - b;
    break;
default:
    cout << "unknown";
}
```

常见误区是忘记 `break`。没有 `break` 时，程序会继续执行后面的 `case`。

### 逻辑错误调试

逻辑错误是程序能编译、能运行，但答案不对。调试思路是“缩小问题范围”。

常用方法：

- 在关键位置输出中间变量。
- 用很小的样例手算，再和程序结果对比。
- 检查循环边界，如 `i < n` 还是 `i <= n`。
- 检查分支是否真的进入。
- 使用断点逐行看变量变化。

### 枚举思想

枚举就是把可能情况一个个试出来。

```cpp
for (int x = 0; x <= 100; x++) {
    if (x * x == 64) {
        cout << x << endl;
    }
}
```

枚举适合规模不大、规则清晰的问题。关键是明确“枚举什么”和“怎样判断合法”。

### 标志变量

标志变量用于记录某件事是否发生。

```cpp
bool found = false;
for (int i = 0; i < n; i++) {
    if (a[i] == target) {
        found = true;
        break;
    }
}
```

`found` 的意义要清晰，不能一会儿表示“找到了”，一会儿又表示“还没检查完”。

### 函数与参数

函数把一段代码封装成一个可复用的任务。

```cpp
int add(int a, int b) {
    return a + b;
}
```

形参是函数定义里的变量，实参是调用函数时传进去的值。

```cpp
int x = 1;
int y = 2;
add(x, y);
```

默认传值时，函数内部修改形参不会改变外部变量。想改变外部变量，通常要用引用或指针。

### 数组与下标

长度为 `n` 的数组，下标范围是 `0` 到 `n - 1`。

```cpp
int a[5] = {1, 2, 3, 4, 5};
cout << a[0];  // 第一个
cout << a[4];  // 最后一个
```

访问 `a[5]` 是越界。越界不一定立刻报错，但结果是不可靠的。

### vector 常见接口

`vector` 是可变长顺序容器。

常用接口：

- `push_back(x)`：在末尾加入元素。
- `pop_back()`：删除末尾元素。
- `size()`：当前元素个数。
- `empty()`：是否为空。
- `clear()`：清空元素。
- `v[i]`：按下标访问。

数组大小固定，`vector` 可以扩容。但 `vector` 扩容时可能搬移原有元素，导致原来的指针、引用或迭代器失效。

### 字符数组、string 与 const char*

字符数组是保存字符的数组，C 风格字符串通常以 `'\0'` 结尾。`string` 是 C++ 提供的字符串类，更适合初学者使用。

```cpp
char s1[] = "hello";
string s2 = "hello";
const char* s3 = "hello";
```

`const char*` 常指向字符串字面量，不能直接修改其中字符。`string` 支持拼接、长度、比较等更自然的操作。

### 结构体案例

结构体适合把相关数据放在一起。

```cpp
struct Student {
    string name;
    int score;
};

Student s;
s.name = "Alice";
s.score = 90;
```

当一个对象有多个相关属性时，用结构体比用多个独立数组更清楚。

### 递推、递归与分治

递推是从已知初始状态一步步算后续状态，例如斐波那契数列。

```cpp
f[1] = 1;
f[2] = 1;
for (int i = 3; i <= n; i++) {
    f[i] = f[i - 1] + f[i - 2];
}
```

递归是函数调用自己。它必须有递归出口。

```cpp
int fact(int n) {
    if (n == 1) return 1;
    return n * fact(n - 1);
}
```

分治是把大问题拆成小问题，再合并答案。归并排序、快速排序都是典型分治。

### 动态规划

动态规划适合有重叠子问题的问题。核心是定义状态和状态转移。

以爬楼梯为例：

```cpp
dp[1] = 1;
dp[2] = 2;
for (int i = 3; i <= n; i++) {
    dp[i] = dp[i - 1] + dp[i - 2];
}
```

记忆化搜索是“递归 + 保存结果”，自底向上 DP 是按顺序填表。两者本质都在避免重复计算。

## 面向对象程序设计基础

### Makefile

Makefile 描述工程如何编译、链接、清理。最小例子：

```makefile
main: main.o student.o
	g++ main.o student.o -o main

main.o: main.cpp student.h
	g++ -c main.cpp

student.o: student.cpp student.h
	g++ -c student.cpp

clean:
	del *.o main.exe
```

每条规则通常包含目标、依赖和命令。命令行前面通常需要制表符。Makefile 不是 C++ 代码，而是构建说明。

### Makefile 中的宏定义

Makefile 里可以用变量减少重复。

```makefile
CXX = g++
CXXFLAGS = -Wall -std=c++17

main: main.o
	$(CXX) $(CXXFLAGS) main.o -o main
```

`$(CXX)` 会被替换成 `g++`。这和 C++ 里的宏不是同一个阶段的东西。

### 栈内存与堆内存

局部变量通常在栈上管理，进入作用域创建，离开作用域自动销毁。

```cpp
void f() {
    int x = 10;  // 栈上变量
}
```

`new` 申请的对象在堆上，生命周期由程序员控制。

```cpp
int* p = new int(10);
delete p;
p = nullptr;
```

常见错误包括忘记 `delete`、重复 `delete`、释放后继续使用指针。

### 访问控制

`public` 表示类外可以访问，`private` 表示只能在类内部访问。`protected` 在继承中使用，入门阶段可先理解为“派生类能访问，但类外不能直接访问”。

```cpp
class Student {
private:
    int score;
public:
    void setScore(int s) {
        score = s;
    }
};
```

封装不是为了“藏起来”，而是为了让对象状态只能通过合理接口改变。

### this 指针

成员函数内部隐含一个 `this` 指针，指向当前调用该函数的对象。

```cpp
class Counter {
private:
    int value;
public:
    void set(int value) {
        this->value = value;
    }
};
```

`this->value` 是成员变量，右侧 `value` 是形参。

### 构造函数

构造函数在对象创建时自动调用，负责初始化对象。

常见形式：

```cpp
class Point {
private:
    int x, y;
public:
    Point() : x(0), y(0) {}
    Point(int x, int y) : x(x), y(y) {}
};
```

委派构造函数是一个构造函数调用另一个构造函数完成公共初始化。

```cpp
Point() : Point(0, 0) {}
```

构造函数没有返回类型，不能写成 `void Point()`。

### 析构函数

析构函数在对象销毁时自动调用，通常用于释放资源。

```cpp
class Array {
private:
    int* data;
public:
    Array(int n) {
        data = new int[n];
    }
    ~Array() {
        delete[] data;
    }
};
```

如果类中没有手动管理资源，通常不需要自己写析构函数。需要写析构函数的典型情况是类拥有动态内存、文件句柄或其他外部资源。

### 拷贝构造什么时候调用

拷贝构造用于“用已有对象创建新对象”。

```cpp
Student a;
Student b = a;      // 调用拷贝构造
Student c(a);       // 调用拷贝构造
```

函数按值传参、按值返回对象时，也可能涉及拷贝构造或被编译器优化。

### 继承访问与向上转换

派生类继承基类后，基类的 `public` 成员仍可作为接口使用，`private` 成员不能被派生类直接访问。

向上转换是把派生类当成基类使用：

```cpp
Dog d;
Animal* p = &d;
```

如果用基类对象接收派生类对象，会发生对象切片，派生类特有部分会丢失。

### 虚函数、override 与纯虚函数

虚函数允许通过基类指针或引用调用派生类版本。

```cpp
class Animal {
public:
    virtual void speak() {}
};

class Dog : public Animal {
public:
    void speak() override {}
};
```

`override` 建议写上，因为它能让编译器检查你是否真的覆盖了基类函数。

纯虚函数表示基类只规定接口：

```cpp
class Shape {
public:
    virtual double area() = 0;
};
```

含纯虚函数的类是抽象类，不能直接创建对象，但可以定义指针或引用。

## 数据结构与算法

### Master Theorem 与 Akra-Bazzi Theorem

Master Theorem（主定理）用于分析“把一个问题平均分成若干个相同规模的小问题”的递推式：

```text
T(n) = aT(n / b) + O(g(n))
```

其中：

- `a`：每次分成多少个子问题；
- `n/b`：每个子问题的规模；
- `O(g(n))`：拆分问题和合并答案所做的额外工作；
- `n^(log_b a)`：所有子问题本身带来的“基准工作量”。

把 `g(n)` 和 `n^(log_b a)` 比较，可以得到三种常见情况：

1. 若 `g(n) = O(n^(log_b a - ε))`，额外工作更小，则 `T(n) = Θ(n^(log_b a))`。
2. 若 `g(n) = Θ(n^(log_b a) log^k n)`，两者同级，则 `T(n) = Θ(n^(log_b a) log^(k+1) n)`。
3. 若 `g(n) = Ω(n^(log_b a + ε))`，并满足常见的正则条件，则额外工作更大，`T(n) = Θ(g(n))`。

例如归并排序把数组分成两半，分别排序，再用线性时间合并：

```text
T(n) = 2T(n/2) + O(n)
```

这里 `a=2、b=2、g(n)=n`，而 `n^(log_2 2)=n`，属于第二种情况，所以时间复杂度是 `Θ(n log n)`。

Akra-Bazzi Theorem（A-B 定理）可以处理子问题大小不相同的递推式：

```text
T(n) = Σ a_i T(b_i n) + O(g(n))
```

先求出满足 `Σ a_i(b_i^p)=1` 的 `p`，再使用：

```text
T(n) = Θ(n^p(1 + ∫[1,n] g(u)/u^(p+1) du))
```

例如 `T(n)=T(n/2)+T(n/4)+O(n)` 的两个子问题并不一样，主定理不能直接套用。A-B 定理先由 `(1/2)^p+(1/4)^p=1` 求得 `p≈0.694`，代入公式后得到 `T(n)=Θ(n)`。

初学时可以这样判断：子问题等大时优先看主定理；子问题不等大时，再考虑 A-B 定理。

### 最大总和区间

最大总和区间也叫最大子数组问题：在数组中找一段**连续**区间，使区间内元素之和最大。例如 `[-2, 3, -1, 4, -5]` 的答案是 `[3, -1, 4]`，最大和为 `6`。

分治法把数组从中间分成左右两半。最优区间只可能有三种位置：

1. 完全在左半边；
2. 完全在右半边；
3. 跨过中点，同时包含左右两边的元素。

前两种递归求解。第三种不能随便选左右两段，而应当：

- 从中点向左累加，找“和最大的后缀”；
- 从中点右侧向右累加，找“和最大的前缀”；
- 两者拼起来，就是跨过中点的最大区间。

以 `[-2, 3, -1 | 4, -5, 2]` 为例，左半边以 `-1` 结尾的最大后缀是 `[3,-1]`，和为 `2`；右半边以 `4` 开头的最大前缀是 `[4]`，和为 `4`；跨中点的最大和就是 `2+4=6`。

每层递归扫描一次区间来求前缀和后缀，共有 `log n` 层，因此递推式为 `T(n)=2T(n/2)+O(n)`，时间复杂度是 `O(n log n)`，递归栈空间为 `O(log n)`。

### 最长公共子序列

最长公共子序列（LCS）是在两个序列中，找出保持原来先后顺序、但不要求连续的最长公共部分。例如 `ABCBDAB` 和 `BDCABA` 的一个 LCS 是 `BCBA`，长度为 `4`。

设 `dp[i][j]` 表示字符串 `A` 的前 `i` 个字符与字符串 `B` 的前 `j` 个字符的 LCS 长度：

```text
如果 A[i-1] == B[j-1]：dp[i][j] = dp[i-1][j-1] + 1
否则：                 dp[i][j] = max(dp[i-1][j], dp[i][j-1])
```

字符相等时，可以把它接到之前的公共子序列后面；字符不等时，说明这两个末尾字符不能同时选，尝试分别舍去一个，取较大结果。边界 `dp[0][j]` 和 `dp[i][0]` 都是 `0`。

普通二维动态规划需要 `O(mn)` 时间和 `O(mn)` 空间。如果只求长度，不需要还原具体序列，可以使用滚动数组：计算第 `i` 行时只依赖第 `i-1` 行和当前行左侧，所以只保留两行，空间降为 `O(n)`。

```cpp
vector<int> prev(n + 1, 0), cur(n + 1, 0);
for (int i = 1; i <= m; ++i) {
    fill(cur.begin(), cur.end(), 0);
    for (int j = 1; j <= n; ++j) {
        if (A[i - 1] == B[j - 1])
            cur[j] = prev[j - 1] + 1;
        else
            cur[j] = max(prev[j], cur[j - 1]);
    }
    swap(prev, cur);
}
// prev[n] 就是答案
```

这里“滚动”不是移动数组元素，而是让 `prev` 和 `cur` 交换角色、循环复用空间。

### 向量插入、删除与扩容

向量通常基于连续数组。插入中间位置时，后面的元素要整体后移；删除中间位置时，后面的元素要整体前移。

当容量不够时，向量会申请更大的连续空间，把旧元素搬过去，再释放旧空间。因为扩容不是每次都发生，所以 `push_back` 的均摊复杂度通常是 `O(1)`，但某一次扩容本身可能是 `O(n)`。

### 均摊分析

均摊分析回答的问题是：一串操作中偶尔会出现一次很贵的操作，但**平均到每次操作**究竟要花多少时间。它不是概率意义上的平均，也不依赖“运气好”，而是保证任意一串合法操作的总成本不会太高。

例如动态数组容量按两倍扩展。第 1、2、4、8……次容量不足时，要搬移已有元素，看起来某次 `push_back` 是 `O(n)`；但连续插入 `n` 个元素时，搬移次数总和最多是：

```text
1 + 2 + 4 + ... + n/2 < n
```

再加上 `n` 次普通插入，总工作量仍为 `O(n)`，所以每次插入的均摊复杂度为 `O(1)`。

常用的三种分析技巧：

- **聚合法**：先算一串操作的总成本，再除以操作次数；上面的扩容例子就是聚合法。
- **记账法**：便宜操作时多收一点“费用”，把余额留给以后昂贵的操作。例如每次插入收 3 元，其中 1 元做本次插入，剩余费用支付将来的搬移。
- **势能法**：用一个数表示数据结构中积累的“待处理工作”。便宜操作增加势能，昂贵操作消耗势能。

常见误区是把“均摊 `O(1)`”理解成“每一次都是 `O(1)`”。它只保证长期总成本；对实时性要求很高的程序，偶发的 `O(n)` 仍可能需要特别处理。

### 插值查找

插值查找用于**有序数组**。二分查找总是翻到书的正中间；插值查找则像查字典：要找以 `W` 开头的单词，通常会直接翻到靠后的位置，而不是先翻中间。

在当前搜索范围 `[left,right]` 中，它根据目标值 `x` 在首尾值之间所占的比例估计位置：

```text
pos = left + (x - a[left]) * (right - left)
             / (a[right] - a[left])
```

例如数组值大致均匀分布在 `0` 到 `1000`，要找 `900`，第一次就会猜到约 90% 的位置。之后根据 `a[pos]` 与 `x` 的大小缩小范围。

- 数据有序且分布接近均匀时，平均时间复杂度可达到 `O(log log n)`；
- 分布很不均匀时，猜测可能总靠近一端，最坏会退化为 `O(n)`；
- 空间复杂度为 `O(1)`。

实现时必须先确认 `x` 位于 `a[left]` 和 `a[right]` 之间，并处理 `a[left] == a[right]`，否则公式会除以零。计算乘法时还应使用足够大的整数类型，避免溢出。

### 位图

位图可以想成一排只有“亮”和“灭”两种状态的小灯。第 `x` 盏灯亮，表示整数 `x` 存在；灯灭，表示它不存在。例如要记录 0 到 999 中哪些数字出现过，只需 1000 个 bit，约 125 字节。

通常用一个机器整数保存一组灯。若每个整数有 64 位，则数字 `x` 位于第 `x/64` 个整数的第 `x%64` 位：

```cpp
vector<unsigned long long> bits((maxValue + 64) / 64, 0); // 全部初始化为 0

bits[x / 64] |= 1ULL << (x % 64);       // 设置：让 x 对应的灯亮
bits[x / 64] &= ~(1ULL << (x % 64));    // 清除：让 x 对应的灯灭
bool exists = bits[x / 64] & (1ULL << (x % 64)); // 查询
```

快速初始化时，可以在创建数组时填 `0`，或对已有连续存储使用 `fill(bits.begin(), bits.end(), 0)`。初始化仍需写完所有机器字，复杂度为 `O(U/w)`，其中 `U` 是值域大小，`w` 是一个机器字的位数；只是位图很紧凑，所以实际速度通常很快。

位图适合值域明确、元素能映射成非负整数的问题，如判重、筛素数。若值域极大但实际元素很少，位图会浪费空间，此时哈希集合通常更合适。

### 列表插入、删除、复制与析构

链表插入删除的核心是改指针。

插入节点时，要先让新节点连上后继，再让前驱连上新节点，避免断链。删除节点时，要先保存要删的节点，再把前驱和后继接起来，最后释放被删节点。

如果链表类要支持复制，必须深复制每个节点。浅复制会让两个链表指向同一批节点，析构时容易重复释放。

### 直方图最大矩形

直方图最大矩形可以用单调栈解决。栈中保存高度递增的柱子下标。当遇到更矮的柱子时，说明栈顶柱子的右边界确定了，可以弹出并计算以它为高度的最大矩形。

直觉是：每根柱子都要找到左边第一个比它矮的位置和右边第一个比它矮的位置，这两个边界决定它能扩展多宽。

### 括号匹配问题

括号匹配要求每个右括号都能找到类型相同、位置正确的左括号，例如 `([{}])` 合法，而 `([)]` 不合法。

栈的“后进先出”正好对应括号的嵌套关系：最后出现的左括号，必须最先被关闭。

扫描字符串时：

1. 遇到 `(`、`[`、`{`，把它压入栈；
2. 遇到右括号，若栈为空，说明它没有左括号配对；
3. 若栈顶不是对应的左括号，说明嵌套顺序错误；
4. 匹配成功则弹出栈顶；
5. 扫描结束后，栈也必须为空，否则还有左括号没关闭。

```cpp
bool matched(const string& s) {
    stack<char> st;
    for (char c : s) {
        if (c == '(' || c == '[' || c == '{') {
            st.push(c);
        } else if (c == ')' || c == ']' || c == '}') {
            if (st.empty()) return false;
            bool ok = (c == ')' && st.top() == '(') ||
                      (c == ']' && st.top() == '[') ||
                      (c == '}' && st.top() == '{');
            if (!ok) return false;
            st.pop();
        }
    }
    return st.empty();
}
```

扫描一次即可，时间复杂度是 `O(n)`，最坏情况下栈占 `O(n)` 空间。

### 最大栈与最大队列

最大栈要在普通的 `push`、`pop` 之外，用 `O(1)` 时间回答“当前最大值是多少”。做法是再准备一个辅助栈：每压入一个普通元素，辅助栈也压入“到当前位置为止的最大值”。

例如依次压入 `3、1、5、2`，两个栈是：

```text
数据栈：3  1  5  2
最大栈：3  3  5  5
```

两个栈同步弹出，所以最大栈的栈顶永远是当前最大值。所有操作都是 `O(1)`，代价是 `O(n)` 额外空间。

最大队列更麻烦，因为新元素从队尾进入、旧元素从队头离开。可以用一个双端队列保存“仍有机会成为最大值”的候选者，并让它们从队头到队尾单调递减：

- 新元素 `x` 入队时，从候选队尾删除所有小于等于 `x` 的值，因为它们比 `x` 小、还比 `x` 更早离开，不可能再成为最大值；然后把 `x` 加到队尾。
- 普通队头出队时，如果它正好等于候选队头，也把候选队头删除。
- 候选队头就是当前最大值。

每个元素最多进入、离开候选队列各一次，因此各操作的均摊复杂度是 `O(1)`。它也正是求滑动窗口最大值的常用方法。


### Huffman算法

Huffman（哈夫曼）算法根据字符出现频率生成一种前缀编码：出现越频繁的字符，编码通常越短，从而减少总存储量。“前缀编码”表示任何字符的编码都不是另一个字符编码的前缀，因此解码时不会产生歧义。

构造 Huffman 树时：

1. 把每个字符看成一个节点，权值是它的出现次数；
2. 将所有节点放入小根堆；
3. 每次取出权值最小的两个节点，合并成一个新节点，新权值为二者之和；
4. 把新节点放回堆中，直到堆中只剩根节点；
5. 从根出发，走左边记 `0`，走右边记 `1`，到叶子经过的路径就是字符编码。

例如频率为 `A:5、B:2、C:1、D:1`。先合并 `C` 和 `D` 得到权值 `2`，再把这个节点与 `B` 合并得到 `4`，最后与 `A` 合并。频率最高的 `A` 离根最近，编码最短。

若有 `k` 种字符，使用小根堆建树的时间复杂度是 `O(k log k)`。Huffman 编码在已知频率、字符逐个编码且编码长度为整数的前提下，能得到最小的加权路径长度。

### 最大子数组和

最大子数组和要求从数组中选择一段**连续且非空**的元素，使总和最大。例如数组 `[-2, 3, -1, 4, -5]` 的最大子数组是 `[3,-1,4]`，答案为 `6`。

Kadane 算法扫描一次数组。令 `cur` 表示“必须以当前位置结尾的最大子数组和”，那么到元素 `a[i]` 时只有两种选择：

- 从 `a[i]` 重新开始；
- 把 `a[i]` 接到前一个最优结尾后面。

因此 `cur = max(a[i], cur + a[i])`。再用 `best` 记录所有 `cur` 中的最大值。

```cpp
int best = a[0], cur = a[0];
for (int i = 1; i < n; i++) {
    cur = max(a[i], cur + a[i]);
    best = max(best, cur);
}
```

例如扫描 `[-2, 3, -1, 4]` 时，`cur` 依次为 `-2、3、2、6`。在 `3` 处重新开始，是因为带上前面的 `-2` 只会让结果变小。

算法时间复杂度为 `O(n)`，额外空间为 `O(1)`。不能把 `cur` 和 `best` 初始化为 `0`，否则当数组全是负数时会错误地返回空数组的和 `0`；初始化为 `a[0]` 才能保证选择非空区间。若还要输出区间位置，可在“重新开始”和更新 `best` 时分别记录左右端点。

### AVL 树

AVL 树是严格控制高度差的二叉搜索树。插入或删除后，如果某个节点左右子树高度差超过限制，就通过旋转修复。

常见旋转类型：

- LL：右旋。
- RR：左旋。
- LR：先左旋再右旋。
- RL：先右旋再左旋。

插入通常修复第一个失衡祖先即可；删除后高度可能继续变化，可能需要继续向上检查。

设最靠近插入位置的失衡节点为 `z`，`z` 较高的孩子为 `y`，`y` 较高的孩子为 `x`。观察从 `z` 到 `y`、再到 `x` 的方向，就能判断旋转方式：

- **LL**：两步都向左。对 `z` 右旋，`y` 上升，`z` 成为 `y` 的右孩子。
- **RR**：两步都向右。对 `z` 左旋，`y` 上升，`z` 成为 `y` 的左孩子。
- **LR**：先左后右。先对 `y` 左旋，把它转成 LL，再对 `z` 右旋。
- **RL**：先右后左。先对 `y` 右旋，把它转成 RR，再对 `z` 左旋。

以 LL 为例，插入 `30、20、10` 后，`30` 的左子树比右子树高 2：

```text
    30              20
   /      右旋     /  \
  20      ---->   10  30
 /
10
```

旋转只改变局部连接，不会破坏二叉搜索树的中序顺序。每次旋转后，要先更新较低节点的高度，再更新较高节点的高度。

插入时，修复从下往上遇到的第一个失衡节点后，整棵子树高度通常恢复，可以停止。删除时即使当前节点恢复平衡，子树总高度仍可能下降，导致更高祖先继续失衡，因此要一路向根检查并可能多次旋转。查找、插入和删除都保持 `O(log n)`。

### 区间树

区间树解决的是“许多区间之间有没有重叠”的问题。例如教室已经被预约了 `[8,10]`、`[13,15]`、`[16,19]` 三个时间段，现在有人想预约 `[14,17]`，需要快速找出与它冲突的预约。

如果逐个检查已有区间，每次查询最坏要看 `n` 个区间。区间树则把每个区间存进一棵平衡二叉搜索树：

- 按区间的左端点排序；
- 每个节点除了保存自己的 `[left,right]`，还保存整棵子树中最大的右端点 `maxRight`。

上面三个预约区间可以组成这样一棵区间树。节点中斜杠后面的数字是 `maxRight`：

```text
                [13,15] / maxRight=19
                 /                  \
    [8,10] / maxRight=10    [16,19] / maxRight=19
```

它仍然是一棵按左端点排列的二叉搜索树：`8 < 13 < 16`。根节点自己的右端点虽然是 15，但它的右子树中存在 `[16,19]`，所以根的 `maxRight` 是整个子树最大的右端点 19。

两个闭区间 `[a,b]` 和 `[L,R]` 相交的条件是：

```text
a <= R 并且 L <= b
```

现在查询新预约 `[14,17]` 与哪些区间冲突：

1. 根节点 `[13,15]` 与 `[14,17]` 相交，因此它是一个答案；
2. 左子树的 `maxRight=10`，小于查询区间左端点 14，说明左子树所有预约最晚在 10 结束，可以整棵跳过；
3. 右子树的 `[16,19]` 与 `[14,17]` 相交，因此它也是答案。

最终找到两个冲突区间：`[13,15]` 和 `[16,19]`，而 `[8,10]` 无需真正比较。一般来说：

- 若一棵子树的 `maxRight < L`，其中所有区间都在查询区间 `[L,R]` 之前结束，可以剪枝；
- 若当前节点的左端点已经大于 `R`，那么按左端点排列在它右侧的区间开始得更晚，也可以跳过。

`maxRight` 可以理解为一块路牌：“这条支路最远能到哪里？”如果连查询区间的起点都到不了，就没有必要进去搜索。

用平衡树实现时，插入、删除和寻找一个重叠区间通常是 `O(log n)`。若要输出所有 `k` 个重叠区间，还需要花时间输出答案，常见复杂度为 `O(log n+k)`。区间树存的是许多个任意区间；它和下一节维护数组下标范围的线段树不是同一种结构。

### 线段树

线段树解决的是“数组经常修改，同时还要经常查询一段范围”的问题。例如数组表示每天的销售额，我们会反复执行：

- 把第 4 天的销售额改为 20；
- 查询第 2 天到第 6 天的销售总额。

直接累加一次区间需要 `O(n)`；若事先计算前缀和，查询虽是 `O(1)`，但每次修改后可能要更新后面大量前缀和。线段树让修改和查询都能较快完成。

假设数组有 8 个元素，线段树可以看成一份分层统计表：

```text
                         [1,8]
                    /             \
                [1,4]             [5,8]
               /     \           /     \
            [1,2]   [3,4]     [5,6]   [7,8]
```

每个节点保存自己负责区间的答案。例如维护区间和时，`[1,4]` 保存第 1 到第 4 个元素之和，父节点的值等于两个孩子之和。

查询 `[2,6]` 时，不必逐个访问 2、3、4、5、6：

- `[3,4]` 和 `[5,6]` 被查询范围完全包含，直接取节点中保存的和；
- `[1,2]` 只部分相交，继续向下找到位置 2；
- `[7,8]` 完全不相交，整棵跳过。

修改第 4 个元素时，只需沿 `[1,8] → [1,4] → [3,4] → [4,4]` 找到叶子，再从下向上重新计算经过的节点，所以不会影响树中无关的部分。

建树需要 `O(n)`，单点修改和区间查询都是 `O(log n)`，常用数组实现需要约 `4n` 空间。若要给整个区间统一加一个数，可以使用懒标记：先把“这整段以后都要加 5”记在较高节点，真正访问孩子时再下传，避免立刻修改每个元素。

### KD树

KD 树解决的是多维空间中的查找问题。最容易理解的是二维地图：已知许多商店的坐标 `(x,y)`，现在要查询“离我最近的商店是哪一家”，或者“这个矩形区域内有哪些商店”。若逐个计算距离，一次查询需要检查全部 `n` 个点。

KD 树不断用一条线切分空间。二维情况下可以这样建树：

1. 第一层按 `x` 坐标选择中间的点，竖着切一刀；左子树放左边的点，右子树放右边的点；
2. 第二层改按 `y` 坐标，横着切一刀；下方放左子树，上方放右子树；
3. 下一层重新按 `x` 切，两个维度轮流使用。

选择中位数附近的点，可以避免树明显偏向一边。最终每个子树都对应地图上的一块区域。

查询最近点时，先根据目标坐标进入更可能的一侧，并不断更新“目前找到的最近距离”。回溯到一条分割线时，比较目标点到分割线的距离：

- 若分割线都比当前答案远，那么线另一边的所有点只会更远，可以整块区域跳过；
- 若分割线比当前答案近，另一边仍可能藏着更近的点，也要进去检查。

例如当前最近商店距离为 3 千米，而目标点离分割线有 5 千米，那么跨过分割线后的任何商店至少也相距 5 千米，无需搜索另一侧。这种“跳过整块不可能区域”的做法叫剪枝。

在维度较低、树较平衡、点分布正常时，查询通常很快，常近似看作 `O(log n)`；但最坏情况下可能几乎无法剪枝，退化为 `O(n)`。维度很高时，各区域越来越难排除，KD 树也会逐渐失去优势。

### 红黑树

红黑树首先是一棵二叉搜索树，因此左子树的键较小、右子树的键较大。颜色本身不存储业务信息，它只是用来限制树不能长得过分倾斜。

理解红黑树，重点抓住两条约束：

- **红色不能连续**：红节点的孩子必须是黑色，不能出现“红父亲—红孩子”。但这不表示颜色必须严格一红一黑，黑节点下面仍可以是黑节点。
- **黑高度一致**：从同一个节点出发，到它下面任意空叶子的所有路径，经过的黑节点数量必须相同。

为什么这能保持平衡？因为最短路径可能全是黑节点；最长路径可以在两个黑节点之间插入一个红节点，但红色不能连续，所以最长路径至多约为最短路径的两倍。树高因此仍是 `O(log n)`。

#### 插入后如何恢复

新节点先染成红色，因为插入红节点不会改变路径上的黑节点数量。若父节点是黑色，规则没有被破坏；若父节点也是红色，就出现“红红冲突”。设父节点的兄弟为叔叔：

- **叔叔是红色**：把父亲和叔叔染黑、祖父染红。局部红红冲突消失，但祖父可能又和它的父亲相邻为红，因此继续向上检查。
- **叔叔是黑色**：通过旋转把祖父、父亲和新节点整理成高低合适的形状，再重新着色。若三者是折线形 LR/RL，先旋转父亲变成直线；然后旋转祖父，让原父节点升到中间，并把它染黑、原祖父染红。

最后始终把根染黑。

#### 删除后如何恢复

删除红节点通常无需调整，因为黑高度没有变化。若删掉黑节点并用一个红孩子替代，把孩子染黑即可补回缺少的黑色。

最麻烦的是删除黑叶子：经过这一侧的路径少了一个黑节点，常把这个位置称为“双黑”。恢复时观察它的兄弟：

- 兄弟是红色：旋转父节点并交换父亲、兄弟颜色，先转成更容易处理的“黑兄弟”；
- 黑兄弟的两个孩子也黑：把兄弟染红，相当于从兄弟一侧拿走一个黑色；若仍不平衡，就把“双黑”向父节点上移；
- 黑兄弟有红孩子：通过一次或两次旋转，并重新着色，让两边重新具有相同黑高度，结束调整。

旋转负责改变树的形状，重新着色负责修复红色相邻和黑高度。调整最多沿树高进行，因此红黑树的查找、插入和删除都是 `O(log n)`。

### 哈希表

哈希表解决的是“根据一个键快速找到对应数据”的问题。例如根据学号查学生信息。如果把所有学生依次放在普通数组中，每次可能要从头比较到尾；哈希表希望通过学号直接算出它大概存在哪里。

哈希函数把键转换成数组下标：

```text
index = hash(key) % capacity
```

数组中的每个位置通常称为一个桶。例如容量为 10，某学号计算出的哈希值是 123，那么它会被安排到 `123 % 10 = 3` 号桶。查找时用同样的公式直接去 3 号桶。

但不同的键可能得到同一个下标，这叫哈希冲突。例如 123 和 203 除以 10 的余数都是 3。冲突无法完全避免，常见解决方式有：

- **链地址法**：3 号桶不只放一个元素，而是放一个小链表或动态数组。所有落到 3 号桶的元素都存进去，查找时再比较真正的键。
- **开放定址法**：每个数组位置只放一个元素。3 号位置被占用后，就按规则继续尝试 4、5、6……等位置，直到找到空位。查找时也必须沿同一条路线探测。

装载因子 `α = 元素个数 / 桶数量` 表示哈希表有多拥挤。元素越来越多时，冲突会变多，查找也会变慢。此时要申请更大的桶数组，并用新容量重新计算所有元素的位置，这叫 rehash。不能直接把旧下标照搬过去，因为取模的容量已经改变。

当哈希函数分布均匀、装载因子受控时，查找、插入和删除平均为 `O(1)`。这里不是说每次操作绝对只执行一步：若许多键挤在同一桶，最坏仍会退化为 `O(n)`。哈希表适合按键快速查找，但它通常不会像搜索树那样自动保持键的大小顺序。

### 跳表

普通有序链表虽然插入方便，但查找很慢。即使知道目标是 80，也只能从头沿着 `1、3、7、12……` 一个个走，最坏需要 `O(n)`。跳表是在有序链表上增加多层“快速通道”。

```text
第 3 层：1 ---------------- 50 ---------------- 90
第 2 层：1 ------ 20 ------ 50 ------ 70 ------ 90
第 1 层：1 -- 3 -- 7 -- 12 -- 20 -- 35 -- 50 -- 70 -- 80 -- 90
```

查找 80 时，从最高层开始：

1. 从 1 跳到 50，再看 90 已经超过 80；
2. 下降一层，从 50 跳到 70，再看 90 仍然太大；
3. 再下降到底层，从 70 前进到 80。

这样不必访问底层的每个节点。插入新元素时，先找到它在底层的位置，再通过随机方式决定它是否也出现在第 2 层、第 3 层等索引中。通常一个节点晋升到上一层的概率是 `1/2` 或 `1/4`，所以层数越高，节点越少。

跳表的查找、插入和删除期望复杂度都是 `O(log n)`，空间为 `O(n)`；极端随机结果下最坏仍可能是 `O(n)`。它用随机分层代替平衡树复杂的旋转，因此实现相对直观，也方便进行并发操作。

### 完全二叉堆与删除

二叉堆通常用数组表示完全二叉树。对于下标从 0 开始的数组：

- 父节点：`(i - 1) / 2`
- 左孩子：`2 * i + 1`
- 右孩子：`2 * i + 2`

删除堆顶时，用最后一个元素补到堆顶，然后下滤。下滤时不断和更合适的孩子交换，直到堆序恢复。

例如下面是一个小根堆，父节点始终不大于孩子：

```text
        2
      /   \
     5     4       数组表示：[2, 5, 4, 9, 7, 8]
    / \   /
   9   7 8
```

删除堆顶 `2` 时：

1. 把数组最后的 `8` 放到堆顶，数组变为 `[8,5,4,9,7]`；
2. `8` 的两个孩子是 `5` 和 `4`，应与更小的 `4` 交换，数组变为 `[4,5,8,9,7]`；
3. `8` 已经没有孩子，下滤结束。

最终堆顶为当前最小值 `4`，小根堆性质恢复。每次交换向下走一层，完全二叉树的高度为 `O(log n)`，所以删除堆顶也是 `O(log n)`。

### 左式堆

左式堆适合合并两个堆。它维护空路径长度，并让左子树的空路径长度不小于右子树。合并时递归合并右子堆，必要时交换左右孩子。

删除堆顶可以转化为：删除根节点，然后合并左子堆和右子堆。



### 图中的 BFS 与 DFS

图由顶点和边组成。从一个起点出发时，BFS 和 DFS 都能访问所有可到达的顶点，区别在于选择“下一步先看谁”。

#### BFS：一层一层向外扩散

BFS（广度优先搜索）像水波从起点向外扩散：先访问距离起点 1 条边的点，再访问距离 2 条边的点。它使用队列保存“已经发现、等待处理”的顶点。

```text
1. 起点入队，并立即标记为已访问
2. 队列不空时，取出队头 u
3. 检查 u 的每个邻接点 v
4. 若 v 未访问，就标记 v、记录距离，再把 v 入队
```

假设边为 `A-B、A-C、B-D、C-E`，从 A 开始，访问层次是：

```text
第 0 层：A
第 1 层：B、C
第 2 层：D、E
```

因此在无权图中，BFS 第一次到达某点时，走过的边数最少，可以求最短路。应在**入队时**标记访问；若等出队才标记，同一个点可能被多个邻居重复放入队列。

#### DFS：沿一条路尽量走到底

DFS（深度优先搜索）像走迷宫：选择一条路一直向前，走不动时退回最近的岔路口，再尝试其他方向。它可以使用递归，也可以显式使用栈。

```text
DFS(u)：
    标记 u 已访问
    对 u 的每个邻接点 v：
        若 v 未访问，就调用 DFS(v)
```

在上面的图中，一种可能顺序是 `A → B → D`，退回 A 后再走 `C → E`。具体顺序取决于邻接点的存放顺序。DFS 常用于寻找连通块、检测环、拓扑排序和回溯，但它第一次找到的路径不保证最短。

使用邻接表时，BFS 和 DFS 都会至多访问每个顶点一次、检查每条边一次，时间复杂度都是 `O(V+E)`，访问标记和队列或递归栈需要 `O(V)` 空间。若图不连通，要从每个尚未访问的顶点再启动一次搜索，才能遍历整张图。

### 串

字符串匹配要解决的问题是：在长度为 `n` 的主串 `text` 中，寻找长度为 `m` 的模式串 `pattern`。朴素算法每次失败后只把模式串右移一位，之前比较成功的信息全部丢掉，最坏会重复比较 `O(nm)` 次。

#### KMP 算法

KMP 的核心是：失配后不让主串指针后退，而是利用已经匹配部分的前后缀关系，判断模式串可以安全地移动多远。

关键辅助数组叫 `next`，也常写作 `lps`。`lps[i]` 表示 `pattern[0..i]` 中“相同的最长真前缀和真后缀”的长度。“真”表示不能取整个字符串本身。

例如模式串 `ABABAC` 的 `lps` 是 `[0,0,1,2,3,0]`。若前 5 个字符 `ABABA` 已经匹配，比较最后的 `C` 时失败，我们已经知道主串刚刚匹配的结尾是 `ABA`，它也等于模式串开头的 `ABA`。因此前 3 个字符不必重比，可以直接令 `j=lps[4]=3`，从模式串下标 3 继续。

匹配过程可概括为：

```text
i 指向主串，j 指向模式串
字符相等：i、j 都前进
j 到达模式串末尾：找到一次匹配
字符不等且 j>0：j = lps[j-1]，i 不动
字符不等且 j=0：i 前进
```

每次失配都会缩短当前可用的公共前后缀，主串指针始终向前，因此构造 `lps` 需要 `O(m)`，匹配需要 `O(n)`，总时间为 `O(n+m)`，额外空间为 `O(m)`。

#### BM 算法

BM（Boyer-Moore）也利用之前的比较信息，但方向不同：模式串与主串对齐后，它从模式串**最右端向左**比较。一旦失配，根据失配字符和右侧已经匹配的部分，往往能一次右移很多位。

- **坏字符规则**：查看导致失配的主串字符。若它在模式串中出现过，就把模式串中合适的那次出现与它对齐；若完全没出现，可以让模式串直接越过它。
- **好后缀规则**：若模式串右侧已有一段匹配成功，就尝试用模式串中另一个相同片段与这段主串对齐；找不到完整片段时，再尝试让它的后缀和模式串前缀对齐。

例如模式串长度为 6，第一次就发现它的最后一个字符与主串不等，并且这个主串字符根本不在模式串中，那么当前覆盖的 6 个起点都不可能匹配，可以把模式串整体跳到该字符之后。BM 正是尽量从一次失败中提取更多信息。

完整 BM 需要预处理坏字符表和好后缀表，通常需要 `O(m+字符集大小)` 空间。它在普通文本上经常跳得很远，实际比较次数甚至可能少于 `n`；但不同 BM 变体的最坏复杂度不同，简单实现最坏仍可能达到 `O(nm)`。KMP 的优势是最坏也能保证 `O(n+m)`；BM 的优势是善于利用失配信息，在较长模式串和较大字符集上通常有很好的实际速度。
