# ClassMate 历史正确性错误题目清单

> 整理日期：2026-08-01  
> 用途：为后续“回答正确性检查器”和固定回归测试集提供输入。  
> 范围：只收录已有测试报告中明确指出的事实错误、错误算法、无效反例、接口编造、关键条件遗漏和完整答案不一致。路由误判、Token 过高、响应慢、措辞不够友好不计入本清单。

## 1. 使用说明

每个历史错误都应至少转化为以下检查项：

- 原问题：回归测试实际发送给 ClassMate 的问题；
- 错误表现：历史回答为什么不正确；
- 正确性锚点：新回答必须满足的事实；
- 禁止项：新回答不得再次出现的说法；
- 状态：后续版本是否已经复测通过。

建议使用以下错误标签：

| 标签 | 含义 |
|---|---|
| `wrong_algorithm` | 推荐的算法不适合题目约束 |
| `constraint_ignored` | 忽略题面中的范围、可选对象或坐标定义 |
| `invalid_example` | 反例、样例或手算过程不能支持结论 |
| `arithmetic_inconsistency` | 数值计算与文字过程互相矛盾 |
| `unsupported_claim` | 把没有证据的猜测说成事实 |
| `invented_interface` | 编造题目中不存在的类、成员或函数签名 |
| `missed_primary_bug` | 没找到代码真正的主要错误 |
| `incomplete_solution` | 用户要求完整代码，但答案缺失或内部不一致 |
| `concept_overgeneralization` | 把只在部分情况下成立的说法当作普遍定义 |
| `multi_turn_incomplete` | 连续追问没有完整承接前文 |
| `repetition_failure` | 重复生成相同错误内容，无法完成请求 |

## 2. 程序设计题目：已确认错误

### CP-A02 排队打水

- 原问题：有好几个水龙头，每个人打水时间又不一样，我不知道先安排谁，总时间到底怎么算？
- 历史错误：把第二个人的完成时刻写成 3，随后又写出 `1 + 3 + 4 = 7`，手算过程与结论矛盾。
- 正确性锚点：对应示例的完成时刻应为 1、2、4；回答应区分“个人打水时间”和“完成时刻”。
- 标签：`arithmetic_inconsistency`。
- 状态：尚未看到修复后的同题正式复测。

### CP-A04 最短加法序列

- 原问题：我会随便挑前面的两个数相加，但是分支特别多，怎么才能保证找到的还是最短的？
- 历史错误：建议“只保留最大数作为状态的一部分”，会丢失后续相加可能用到的历史数字，无法保证搜索完整。
- 正确性锚点：状态必须保留生成后续数字所需的完整递增序列；可以使用迭代加深和可靠的上界剪枝。
- 标签：`wrong_algorithm`、`constraint_ignored`。
- 状态：尚未看到修复后的同题正式复测。

### CP-A07 线段和点

- 原问题：要挑尽量少的点让每个区间里都有点，我完全不知道该先选哪个点。
- 历史错误：直接建议选择区间右端点，但题目规定只能从给定点集中选点。
- 正确性锚点：应选择“当前区间内最靠右的可用给定点”；如果区间内没有给定点，需要按题意判无解。
- 标签：`constraint_ignored`、`wrong_algorithm`。
- 状态：尚未看到修复后的同题正式复测。

### CP-A18 必选飞弹

- 原问题：本来最长序列我就不太会，现在还有几枚飞弹必须选，我完全不知道怎么把这个条件加进去。
- 历史错误：只修改必选位置的 `dp[i]` 初值，不能保证最终恢复出的序列包含全部必选飞弹。
- 正确性锚点：必须把所有必选位置作为全局约束处理；可以围绕相邻必选点分段求解，再验证高度关系和顺序。
- 标签：`wrong_algorithm`、`constraint_ignored`。
- 状态：尚未看到修复后的同题正式复测。

### CP-W01 BMP 文件信息

- 原问题：文件夹里有题目给的 BMP 附件，你先看题目和附件，再告诉我宽高、数据大小和文件大小应该从哪几个字段读。
- 历史错误：把 `biHeight > 0` 时的像素存储方向说成从上到下。
- 正确性锚点：经典 BMP 中 `biHeight > 0` 表示像素行按自底向上存储；没有真正解析附件时不能声称读到了具体宽高。
- 标签：`constraint_ignored`、`unsupported_claim`。
- 状态：尚未看到修复后的同题正式复测。

### CP-W02 BMP 坐标转换

- 原问题：我处理出来的图上下反了，文件夹里有样例图片，你能结合题目看看我的坐标方向应该怎么换吗？
- 历史错误：先说文件第 0 行是底边，随后又使用与该说法冲突的 `h - 1 - i` 映射，没有先锁定题目的数学坐标定义。
- 正确性锚点：必须分别说明文件行序、内存行序和题目数学坐标；给公式前用一个上下不对称的小图验证方向。
- 标签：`arithmetic_inconsistency`、`constraint_ignored`。
- 状态：尚未看到修复后的同题正式复测。

## 3. 数据结构 PA：已确认错误

### DS019 Interview

- 原问题：有 n 个人依次围圆桌坐，每个新来的人从上一个人开始逆时针数 m 个人再插进去，最后从最后来的人顺时针输出。n 到一百万，我完全不知道该怎么存这个圆桌。
- 历史错误：只推荐普通链表，没有说明链表寻找“第 m 个位置”仍需线性时间。
- 正确性锚点：普通模拟和普通链表按秩寻找都会慢；应利用“逆序删除”和快速寻找第 k 个存活位置的视角，考虑分块计数或秩选择结构。
- 标签：`wrong_algorithm`、`constraint_ignored`。
- 状态：历史报告未记录针对该错误的独立复测。

### DS021 Sort

- 原问题：有个 compare 一次传三个编号，只返回最大和最小，而且调用次数有限，要把这些编号按背后的值排好。我连两个数怎么比较都没想明白，应该从哪开始？
- 历史错误：在缺少 `sort.h` 和调用上限细节时，直接提出“找第三个编号”，但没有解释该编号为何能作为可靠参照。
- 正确性锚点：信息不足时必须明确说明；第三个参数只能使用已经建立顺序关系的参照或经过证明的哨兵策略，不能随便选择。
- 标签：`unsupported_claim`。
- 状态：属于较弱回答，尚未独立复测。

### DS023 Temperature

- 原问题：二维平面上有 20 万个带温度的点，要回答 16 万次矩形里的最低和最高温度，坐标还是 int 全范围。暴力肯定不行，但我没学过二维查询，能给我一个起点吗？
- 历史错误：推荐二维稀疏表和简单坐标离散化；20 万个稀疏点离散后仍可能形成约 `200000 × 200000` 的网格。
- 正确性锚点：只存实际点；优先从 KD 树或题目规定的多级搜索树解释，节点维护包围盒和温度最值，查询完全覆盖节点时直接使用聚合值。
- 标签：`wrong_algorithm`、`constraint_ignored`。
- 状态：尚未看到修复后的同题正式复测。

### DS024 Zuma 超时

- 原问题：Zuma 我直接用 string 的 insert 和 erase，连消也做了，小数据都对，但是五十万长度和五十万次操作会超时。是不是把 string 换成 list 就行？
- 历史错误：把 `list<char>` 当作基本解决方案，忽略了按位序寻找插入点仍是 `O(n)`。
- 正确性锚点：list 只改善已知迭代器位置的插入删除；本题还需要按秩定位，并处理连消后的块边界，方向应是分块数组等结构。
- 标签：`wrong_algorithm`、`constraint_ignored`。
- 状态：后续知识卡片已改善 Zuma 诊断，但该纯对话性能问题仍应保留回归。

- 正确性锚点：严格使用题目真实接口；按操作顺序建立修改链或批量节点，保持旧版本可访问，并满足构造次数限制。
- 标签：`invented_interface`、`wrong_algorithm`。
- 状态：工作区规则更新后复测 84 分，保留防回归。

### OOP-M010#1 vector 迭代器选择题

- 原问题：vector 迭代器失效这题到底怎么选？
- 历史错误：只讲扩容和 erase，漏掉 `clear()` 会使相关迭代器失效，也没有直接完成选择题。

## 6. 课件知识点：已确认错误

### COURSE-D17 Dijkstra 负边反例

- 原问题：Dijkstra 为什么不能有负边，我感觉每次选最小的也没问题。
- 历史错误：使用 `S→A=5、S→B=2、B→A=-4`；Dijkstra 会先确定 B，再把 A 更新为 -2，因此该例不能证明失败。
- 正确性锚点：反例必须让某节点先被确定，随后另一节点通过负边把它的距离改小；例如 `A→B=1、A→C=2、C→B=-3`。
- 标签：`invalid_example`。
- 状态：连续追问版本后来使用了有效反例，单轮题仍需回归。

### COURSE-P20 动态规划状态定义

- 原问题：动态规划的 dp[i] 到底是怎么想出来的，我每次只会照答案抄。
- 历史错误：把 `dp[i]` 普遍定义成“规模为 i 的子问题的最优解”。
- 正确性锚点：动态规划不一定解决最优化问题，状态也不一定只有一个下标；状态应保存区分子问题且足以决定转移的信息。
- 标签：`concept_overgeneralization`。
- 状态：尚未看到独立修复复测。

### COURSE-O09 右值与 std::move

- 原问题：右值引用和 std::move 我完全看不懂，它真的把东西移动了吗？
- 历史错误：把函数返回值统一说成右值，并用“右值不能取地址、没有名字”作为绝对判断。
- 正确性锚点：函数可能返回引用；值类别不能只按有没有名字判断；`std::move` 只进行类型转换，真正的资源移动由移动构造或移动赋值完成。
- 标签：`concept_overgeneralization`。
- 状态：核心 `std::move` 结论正确，但定义仍需回归。

### COURSE-M04#3 AVL 连续插入

- 原问题：这种情况 AVL 具体怎么转，先找哪个节点？（承接按 1、2、3、4 插入）
- 历史错误：只解释插入 3 时对节点 1 左旋，没有说明旋转后再插入 4 时仍平衡、无需再次旋转。
- 正确性锚点：必须完整承接 1、2、3、4 的整个插入过程，并在每一步重新计算平衡状态。
- 标签：`multi_turn_incomplete`。
- 状态：属于部分正确，尚未独立复测。

## 7. 算法内容理解专项：已确认错误

### ALG-U21 B 树孩子区间

- 原问题：普通树一个节点放一个数，B 树为什么要在一个节点里塞一排数？
- 历史错误：根节点 `[2,4,6]` 只画出三个孩子，并给出跨越分隔关键码 4 的 `[3,5]` 区间。
- 正确性锚点：三个关键码把值域分成四个孩子区间；任何孩子负责的范围不能跨越父节点分隔关键码。
- 标签：`invalid_example`、`concept_overgeneralization`。
- 状态：尚未复测。

### ALG-U33 拓扑排序与普通排序

- 原问题：拓扑排序和普通从小到大排序有什么关系？它排出来的顺序为什么可能不唯一？
- 历史错误：把普通排序概括成“结果唯一”，忽略重复关键字和元素身份顺序。
- 正确性锚点：数值排序要求按比较关系排列；若只看值序列可能相同，但重复元素的相对身份顺序未必唯一。拓扑序的不唯一来自没有依赖关系的节点可交换。
- 标签：`concept_overgeneralization`。
- 状态：低严重度，尚未复测。

### ALG-U38 最小生成树与最短路径反例

- 原问题：最小生成树已经让所有边加起来最小了，为什么从起点到某个点还不一定最短？
- 历史错误：反例中的树上路径权值为 2、直接边为 100，树上路径反而更短，不能支持结论。
- 正确性锚点：必须重新计算树上路径和原图最短路径，确保 MST 上的路径严格更长，同时 MST 的全树边权和仍满足最小。
- 标签：`invalid_example`。
- 状态：高严重度，尚未复测。

### ALG-L05#3 最小生成树图示

- 原问题：为什么一个得到最短路径树，一个得到最小生成树？
- 历史错误：使用有向箭头表示最小生成树示例，容易让初学者误以为普通 MST 适用于有向图。
- 正确性锚点：普通 Prim/Kruskal 的教学示例使用无向加权图；若使用箭头仅表示讲解方向，必须明确说明边本身无向。
- 标签：`constraint_ignored`。
- 状态：中等严谨性问题，尚未复测。

### ALG-L05#4 重复无效反例

- 原问题：给一个图说明最小生成树上的路径不一定最短。
- 历史错误：多次声称给出“真正的反例”，却重复使用同一张无效图，输出异常膨胀且没有完成请求。
- 正确性锚点：回答前计算所有相关路径权值；发现反例无效时必须更换图；连续相同段落出现两次应中止并重试。
- 标签：`invalid_example`、`repetition_failure`。
- 状态：高严重度，尚未复测。

## 8. 暂不直接作为正确答案的争议项

### OOP-M010#2 旧 `vector::end()` 是否有效

- 原问题：容量够的时候 push_back 不扩容，那原来的 end 还能用吗？
